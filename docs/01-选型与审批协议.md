# 01 — 初始化、重构及选型审批协议（必须执行）

## 1. 什么时候必须询问所有者

- 新建产品、初始化工程、从零重新生成前后端。
- 对旧系统进行整体重构、UI 框架替换、ORM/数据库切换、目录重整。
- 将管理后台改为另一套前端框架、引入第二套 UI 库或改变 RMDL 设计基础。

普通 CRUD、Bugfix、已锁定架构中的功能增量无需反复发起选型。配置已锁定时不得借“优化”重新选一套。

## 2. 主 Agent 必须向用户展示的选择卡

以下选项由用户决定，Agent 只能标出推荐项和原因，**不能代替选择**。技术能力不足时要解释限制，不能偷偷换栈。

| 决策项 | 可选项 | 推荐规则 | 是否必须问 |
|---|---|---|---|
| 动作 | 新建 / 整体重构 | 不作默认猜测 | 是 |
| 产品类型 | Admin、Data、Portal、Game、Content、Service | 决定预置页面模式；非视觉自由设计许可 | 是 |
| Web 框架 | Vite / Next.js / 无 Web | 后台优先 Vite；公开 SEO/SSR 优先 Next.js | 是（Service 可无 Web） |
| 后端语言 | C#/.NET / Java / Python / Node.js/TypeScript / 无后端 | C#/.NET 为工程默认，但必须让用户选 | 是 |
| 生产关系数据库 | PostgreSQL / MariaDB / SQLite / 无 | PostgreSQL 默认推荐；轻型单机可 SQLite，需明确限制 | 是 |
| 部署方式 | Docker / Linux 原生 / Windows 原生 / 混合 | Docker 为默认推荐，不替用户决定 | 是 |
| 迁移策略（重构） | 渐进替换 / 完整重写 | 默认推荐渐进替换，需用户决定 | 重构必问 |

### 不允许作为普通选项的红线

- React + TS strict + Bun + HeroUI v3 + Tailwind v4 + RMDL Design System 是 Web 前端固定选型；后端可以多语言，前端不能自由改成 Vue/Angular 等。
- 全部 Admin 类型都用 RMDL 的 Admin 视觉基线；没有“自己选择蓝色/紫色/卡片圆角”的产品级自由选项。
- .NET 对应 FreeSql + CodeFirst；仅在兼容性证据充分并经所有者批准 ADR 时允许 EF Core。Dapper 不是可独立承担 CodeFirst 的候选。
- 其他语言 CodeFirst 基线：Java Hibernate/JPA + 版本化迁移；Python SQLAlchemy + Alembic；Node TypeScript + Drizzle。可提出 ADR，但不能不问就改。

## 3. 审批状态机

```text
DISCOVER(只读检查) → PROPOSE(可选项+差异+风险) → DRAFT(用户选型草稿)
    → OWNER_APPROVAL(项目所有者确认) → LOCKED(写入配置并受保护)
    → IMPLEMENT(限定范围的代码修改) → VERIFY(静态+逻辑+视觉)
    → REVIEW(所有者/受托审查) → COMPLETE
```

- `draft` 不允许开工；缺少任何关键选项时不能自动使用所谓默认值。
- `rmdl.project.json` 是锁定选型的可审计结果；只有所有者明确批准后才设置 `governance.state=locked`。
- CLI 允许用户在终端选择选项，生成草稿；只有在用户再次明确确认后才允许将其锁定。
- **真实性限制**：CI 检查 `locked` 状态并不能证实是谁填写了 JSON；必须结合受保护分支、审查规则与提交记录。Agent 不得自行填写虚假批准者。

## 4. 重构额外要求

完成基线审计，再向用户给出：保留技术/更换技术矩阵、业务行为不变清单、关键依赖与风险、组件复用迁移计划、每阶段回滚点、预计会变的页面清单。

不得将全站 UI 一次性“重新发挥”。先改 UI 包和 Token 适配，再选一张标准列表页、一张编辑页做视觉验收；通过后分批迁移。老页面需要保持可运行；外观不一致的中间态必须标识在迁移清单，不能宣称全站已满足 RMDL。

## 5. 建议的提问方式（Agent 应直接使用）

> 我将按 RMDL 初始化/重构这个项目。Web 的 React、TypeScript、Bun、HeroUI v3、Tailwind v4 和统一 UI 标准已经固定。请你选择：① 产品类型；② Vite/Next.js/无 Web；③ 后端语言；④ 生产数据库；⑤ 部署方式；（重构再选⑥渐进替换或完整重写）。我会给出推荐项，但在你确认前不会建立/重写业务代码。确认后会生成锁定选型文件和实施计划。

## 6. 决策变更规则

一旦 locked，常规任务不重新提问；变更需所有者批准、ADR、差异评估、迁移与回退计划，并经过完整 CI/视觉检查。只改变一个选择时，不得隐式改变其他已锁定选择。
