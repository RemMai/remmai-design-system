# ADR-0002 — .NET 11、产品版本绑定与跨会话规则

- 日期：2026-11-16
- 状态：所有者本次会话明确要求修改标准；工作区修订，未发布。
- 决定依据（本次请求原文摘录）：「更新标准，DotNet 版本为 11」「无论是前端还是后端，都要绑定Version」「优先级。foot > menu > header > 单独菜单页」「另外携带一个内部标号，这个内部标号是Git的提交的hash」。所有者另提出 OpenCode 新 session 无法持续遵守标准的问题。

## 决策

1. .NET 应用基线改为 11 / net11.0；精确正式 SDK 由项目验证并锁定，不沿用“11 仍为 RC”的旧快照结论。
2. 根 VERSION 统一产品 MAJOR.MINOR.PATCH，根 CHANGELOG.md 记录变更；内部 gitCommit 从实际构建仓库 HEAD 生成。开发标记 dirty，正式发布拒绝脏工作区。
3. 前端展示严格按所有者最后明确的优先顺序；Menu 底部与既有用户区沉底兼容，Header 使用右侧可用空间，最后兜底独立更新日志菜单页。
4. 用短基线 + 项目 AGENTS.md + OpenCode instructions 持久化规则；CLI/CI 检查可确定字段，真实制品与视觉测试验证运行结果。

## 影响与边界

新增选型字段会让旧业务配置未迁移时检查失败；消费方必须审查并固定新标准 commit。继承的 standardVersion/UI 包版本兼容限制仍为 0.3.0，不伪造组件发布或修改 Registry 审批。共享 Auth 包现有 net10.0/net8.0 不在此次应用标准变更中宣称已升级验证。

全局 OpenCode 指令与项目文件会合并，长篇角色设定/不同领域工作流会竞争上下文且可能与工程约束冲突。项目配置不能替代清理全局冲突规则，也不能替代受保护的 CI。本次不修改个人全局配置。

## 验证与回滚

主库运行 check-repo 与 rmdl-guard 测试，包含版本/SDK 拒绝用例和真实临时 Git 仓库的元数据生成测试。业务项目另执行制品绑定与浏览器验证。

回滚按此次变更的提交/diff 恢复标准、CLI、配置模板和新增文档；业务仓库恢复原已固定标准 commit 及匹配配置、完整制品。不得覆盖本次之前已有的未提交工作。此次未执行发布或外部项目迁移。
