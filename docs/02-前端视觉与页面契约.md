# 02 — 前端视觉与页面契约（UI Contract / 违规即不验收）

## 总体目标

让两个不同后端、不同业务的系统看起来仍是一个团队维护的同一套产品。**只统一颜色不够**：必须统一 DOM 基本结构、组件实现、间距、状态、信息密度、文案风格、交互语义和截图基线。

## 1. 同源机制（最高优先级）

- 工程化 Web 使用 React + TS strict + Bun + HeroUI v3 + Tailwind CSS v4 + Lucide。
- 锁定为 `static-html` 的轻量 Tool 可直接使用 HTML/CSS/JavaScript/图片，无需框架、包管理器或构建步骤；它仍须使用锁定 RMDL 版本的 Tokens CSS，并遵循本契约中的视觉与交互规则。该模式不适用于复杂后台。
- 唯一业务 UI 公共包：`@remmai/rmdl-ui`。严格要求所有项目锁定其版本号或提交 SHA；不要在两个项目分别粘贴 `AppShell`、`AppDataTable` 源码后各自优化。
- 全部核心 Token 从 `packages/tokens/rmdl-colors.css` 或受控版本的 Token 包引入；产品内不得重新定义 `--rmdl-brand-primary`、全局字阶或基本圆角。
- 只有 RMDL UI Maintainer 经版本升级和视觉基线审查可改动公共 UI；业务 Agent 只能通过公开 `variant`、`density`、`slot`、语义 Props 组合。
- 平台差异（如博客内容页、游戏图鉴）可拥有独立内容区块，但不能覆盖统一交互组件的色彩、尺寸、键盘交互、状态含义。

### 1.1 静态交付约定

- 工程化项目必须验证最终 `dist/`（或框架配置的静态输出目录）能独立部署；所有资源使用相对路径或已配置的 OSS/CDN 公共路径，不依赖开发服务器。
- `static-html` 项目以 `index.html` 为入口，所需 CSS、JS、图片和 RMDL Tokens CSS 均随站点目录交付；无需运行构建命令，目录整体上传到 OSS 静态网站托管即可访问。
- 将 `vendor/rmdl/packages/tokens/rmdl-colors.css` 作为版本锁定的 `apps/web/assets/rmdl-tokens.css` 一并提交；业务 CSS 只引用 `--rmdl-*` Token，不修改 Token 源文件。
- 不把密钥、服务端凭据或仅应由服务端执行的逻辑放入前端静态文件。需要服务端功能时改选带后端的架构。
- 两种模式均需检查桌面与移动视口、可访问性、错误/空状态（适用时）和实际托管路径下的资源加载。

## 2. 后台固定外壳（默认不允许变形）

| 规范对象 | RMDL Admin 默认 | 禁止做法 |
|---|---|---|
| 全局导航 | 左侧栏 240px，支持折叠 | 顶部+侧边重复导航、每个功能页换侧栏风格 |
| 顶部栏 | 56px，统一账号/全局操作位置 | 在页面局部再造 80px 导航条 |
| 内容区 | 最大宽度 1440px，左右留白 24px（窄屏自适应） | 每页自由设宽造成参差 |
| 正文 | 14px / 行高约 1.5，标题 24px | 任意生成字号、整页都是 16–18px |
| 间距 | 4/8/12/16/24/32/48px | 13、19、27px 等即兴设计标尺 |
| 圆角 | 8/12/16px，依组件语义使用 | 到处 20–30px 大圆角 |
| 高亮 | 每个视觉任务区通常 1 个 Primary CTA | 一屏多个同权重彩色主按钮 |
| 表格 | 固定表头/行密度、状态标签与操作列规则 | 列表默认变成巨型 Card 瀑布流 |
| 反馈 | 统一 Toast/Empty/Error/Skeleton/Confirm | 页面内重复“操作成功”说明区 |

对小屏必须使用已批准的响应式折叠规则，不得自行重设计移动端导航。若原型阶段暂不支持小屏，明确记录且不能假装响应式完成。

## 3. 固定页面模板（页面启动时先声明一个）

**List**：`AppPageHeader`（标题、可选一句话、最多一个主操作）→ `AppToolbar/AppFilterBar`（只放影响当前数据的过滤）→ `AppDataTable`（分页、排序、空/错/加载）→ 可选批量操作。默认不添加“数据概览”卡片。

**Detail**：紧凑身份栏和状态 → 1 个主信息区 → 按业务有必要的关联表格或时间线。不要把每个字段都做独立 Card。

**Form**：一个主标题 → 逻辑分组表单 → 同一操作区的保存/取消。帮助文案尽量放到字段处；有风险才增加确认步骤。

**Dashboard**：只能展示有真实来源且能驱动行动的数据。无明确业务用途时**不添加 KPI 卡片、趋势图、看板装饰**。

**Workflow**：关键当前状态、待处理事项、决策操作、审计记录；复杂流程可以多步骤，但不得以“酷炫步骤条”替代业务信息。

## 4. 简洁度硬规则与检查项

- 每页仅 **1 个 H1**，标题建议 4–14 个汉字；同义词、面包屑与卡片内不要重复三级标题。
- 页头说明为 **0–1 句**，建议不超过 50 个汉字；只有需要解释权限/风险的页面才适当增加。
- 同一任务区域 **最多 1 个 Primary 操作**；其他为 Secondary、Text 或危险操作分区。
- 列表型页面默认 0 个概览/KPI 卡。超过 0 必须说明它们对当前任务的决策价值（提交视觉评审）。
- 没有真实数据来源，不得放占位图表、虚假统计、随机销量/用户数。
- 过滤器默认精简为高频 2–5 项；其他折叠进“更多筛选”。
- 空状态：一条说明 + 一个可行动建议即可；避免三段解释和多个宣传按钮。
- 图标只传达功能/状态；不要在每个标题旁都加无意义 Emoji/装饰图标。
- 不在卡片内部再嵌套卡片制造层级；优先分隔线、表单分组和表格。
- 列表桌面行高使用已发布组件的 40px（compact）或 48px（standard），不能业务页面私改。

这里给出默认可操作阈值；数字本身不能代替设计评审，真正验收还要看截图、可用性和任务完成效率。

## 6. 机器和人工各自负责什么

**机器可阻断**：未锁定的选型、未批准 UI 依赖、缺少 HeroUI/Tailwind 依赖、TS strict、硬编码色值、未通过的 Playwright 截图对比、构建/测试失败。

**人工必须审**：页面是否啰嗦、信息层级是否合理、表格可用性、文案是否重复、两个项目是否有统一感、截图基线变更是否真正符合用户决策。仅运行 Regex/ESLint 并不能判断“这页很丑/很啰嗦”。

**截图至少覆盖**：Admin List、Detail、Form，以及 loading/empty/error；桌面 1440、移动 390；涉及深色模式时还需 Dark。首次建立视觉金样本需要项目所有者审定，后续变更不可在无人审核下自动更新快照。

## 7. HeroUI 版本纪律

HeroUI v3 使用 `@heroui/react` + `@heroui/styles` 和 Tailwind v4；禁止照抄 v2 的 Provider/组件 API/旧主题配置。实现具体组件前，查对应 v3 文档再映射进 RMDL UI 层。后端栈选型不能成为引入其他 Web 组件库的理由。

## 8. 纯净工作台原则（严禁 AI 宣讲式文案与功能复述）

### 8.1 典型 AI 违规模式（点名阻断）
大模型在生成前端界面时，极易带入“演示 Demo”或“营销落地页（Landing Page）”的惯性思维，产生以下**严重污染控制台体验的垃圾内容（AI Slop）**：
- **底部回显卡片**：在表格或表单下方堆叠 3~4 个卡片，复述用户 Prompt 中的需求（如“🚀 核心功能介绍”、“✨ 智能数据抓取”、“🔔 多通道通知告警”）。
- **页面说明书**：在页面顶部或侧边放置大段“使用指南 / 快速上手 / 本模块操作指南”。
- **虚假统计占位**：在不需要 KPI 的配置页强行塞入 4 个无意义的数字卡片。

### 8.2 结构边界（仅允许 3 类容器）
业务管理后台的标准页面**只允许包含以下三类纯操作容器**：
1. **筛选/工具栏 (Toolbar/Filter)**：搜索框、下拉筛选、新建/批量操作按钮。
2. **核心工作区 (Work Area)**：数据表格 (DataTable)、状态看板、配置表单或详情视图。
3. **操作与分页栏 (Pagination/Footer Actions)**：分页器、提交/取消操作栏。

**严禁出现第四类容器**：即任何形式的“关于本页”、“功能概览”、“系统特点”等静态宣传说明卡片。

### 8.3 允许的文案边界
- 按钮文本：简明动词（≤4 字），如 `新建用户`、`保存配置`、`重试`。
- 输入引导：只允许写在输入框内部的 `placeholder`（如 `请输入用户手机号`）。
- 复杂字段解释：仅允许以问号图标形式存在，通过 `Tooltip` 悬浮呈现，禁止占用页面主要版面。
- 静态门禁 `scripts/rmdl.mjs check` 会对页面内包含“核心功能”、“功能介绍”、“使用说明”等特征词的 JSX 节点直接拦截报错。

### 8.4 派发前端任务时的标准防呆咒语
在向任何 AI Agent 派发前端任务时，直接在需求末尾追加以下标准约束：
> **“遵循 RMDL 纯净工作台原则：仅输出数据与操作控件，严禁在底部生成任何功能介绍卡片、特性列表或使用说明；保持高信息密度，写完通过 `bun vendor/rmdl/scripts/rmdl.mjs check --root .` 检查。”**

## 9. 页面路由权限门禁（严禁未登录直接直穿后台）

1. **未登录绝对阻断**：所有受保护的业务后台路由（除了 `/login`、`/auth/callback`）在渲染前必须经过 `AuthGuard`。
2. **禁止提前透出 DOM**：在确认 Token 有效且 `/api/auth/me` 返回成功之前，界面只允许显示轻量加载状态，严禁先渲染顶栏、侧边栏导航或表格骨架。
3. **自动跳转**：若无 Token 或认证失效，立即调用 `window.location.replace('/login?redirect=' + encodeURIComponent(window.location.pathname))`，确保访客无论直接输入任何深层 URL，首屏必然落地到登录界面。

## 10. Admin 视口与滚动契约（Header/Menu 冻结 + 内容独立滚动 + 用户区沉底）

管理后台必须保证操作视口绝对稳定，禁止产生整页“全屏外壳跟随滚动”的破损体验：

1. **外壳满高与溢出锁定**：
   - 整体外壳 `.rmdl-shell` 锁定 `height: 100vh; max-height: 100vh; overflow: hidden`。
2. **顶部 Header 固定不滚动**：
   - 右侧 `.rmdl-shell__topbar` 设定固定高度（56px / `var(--rmdl-topbar-height)`），`flex-shrink: 0`，视口绝对固定，不随任何滚动移动。
3. **左侧 Menu 固定不滚动 + 导航溢出自滚**：
   - 左侧 `.rmdl-shell__sidebar` 锁定 `height: 100vh; max-height: 100vh; overflow: hidden; display: flex; flex-direction: column`。
   - 导航项容器 `.rmdl-shell__nav-wrapper` 设定 `flex: 1; min-height: 0; overflow-y: auto`，当系统菜单超长时仅在导航区域内部滚动，菜单侧栏整体不晃动。
4. **用户信息区强制沉底**：
   - 用户头像、昵称、退出登录按钮等信息区 `.rmdl-shell__user` 必须位于左侧栏的最底部，通过 `margin-top: auto` 或 Flex 弹性沉底吸附。
5. **右侧 Content 独立滚动**：
   - 右侧主视口内容区 `.rmdl-shell__content` 设定 `flex: 1; min-height: 0; overflow-y: auto`。页面表格或表单高度溢出时，仅右侧 content 内容区自身平滑滚动。
