# 04 — 现有项目 RMDL 迁移操作手册

1. **只读审计**：列出前端框架、UI 依赖、CSS 变量、页面数量、页面模式、后端语言、主 ORM、数据库、当前测试与截图。不要先改文件。
2. **所有者选型**：向用户展示保留/替换矩阵；选定新的 `rmdl.project.json` 草稿，审批后锁定。保留原服务接口和业务逻辑是默认风险最小策略。
3. **迁移计划**：定义批次 `foundations → shell → list → detail/form → dashboard/workflow → cleanup`；每批设验收样本、可回滚版本、未迁移页清单。
4. **统一 Token**：先将业务 CSS 的色值映射为 RMDL Tokens；不得用全局 !important 覆盖原组件来制造表面统一。
5. **接入 UI 核心包**：封装统一 Shell、页头、工具栏、按钮、表格。优先将既有页面“换壳+替换组件”，不是全面重写功能。
6. **样板先行**：至少一张列表页和一张编辑页分别在 1440/390 + Light/Dark 做审查。审查通过后扩展到剩余页面。
7. **逐批门禁**：新增/迁移后的页面严格执行 check+typecheck+lint+test+visual。旧页面尚未迁移时记录债务及截止批次，不以“例外 ADR”永久放行。
8. **最终锁定**：所有目标页迁移完成、快照由所有者审查，移除旧 UI 依赖和旧 Token，然后提高 CI 到全项目必须通过。

推荐先增加 CI/静态扫描作为**信息性检查**，审计并记录基线违规；之后逐批启用硬阻断。不得把现有大规模不合规项目简单标成已完成。
